# sygus-check

An independent checker for solutions to
[SyGuS v2](https://sygus-org.github.io/language/) synthesis problems.

Given a solver's output and the reference `.sy` problem, it answers whether the
solution is correct, and it does so without reusing any part of the solver that
produced it:

* **Semantic check** — the SyGuS constraints are compiled into a single SMT-LIB
  verification condition with the synthesized functions replaced by their
  definitions, and discharged by an external SMT solver (cvc5 by default).
* **Syntactic check** — the checker verifies *itself*, without a solver, that
  each solution term is generated by the grammar declared in its `synth-fun`.
* **Signature check** — the solution must define exactly the functions to
  synthesize, with matching parameter and return sorts.

## Usage

```
./sygus-check <solution-file> <problem.sy>
```

The solution file is what a SyGuS solver prints for `(check-synth)`: a sequence
of `define-fun` commands, optionally wrapped in one pair of parentheses and
optionally preceded by a status atom such as `sat` or `infeasible`.

```
$ ./sygus-check tests/cases/max2-correct.out tests/cases/max2.sy
[syntactic] max2: ok
            term is derivable from start symbol Start
[semantic]  valid
            solver reports unsat: the constraints are entailed
result: correct
```

```
$ ./sygus-check tests/cases/lin-bad.out tests/cases/lin.sy
[syntactic] lin: violation
            term is not derivable from any nonterminal (start symbol is Start)
              no production generates: (* x x)
[semantic]  invalid
            solver reports sat: the constraints can be falsified
            counterexample:
              (
              (define-fun x () Int 1)
              (define-fun y () Int 0)
              )
result: incorrect
```

Exit codes: `0` correct, `1` incorrect, `2` unknown (solver timeout, or a
grammar feature the syntactic check cannot model), `3` usage or parse error.

Useful options:

| option | meaning |
| --- | --- |
| `--solver BIN`, `--solver-arg ARG` | which SMT solver to call, and extra flags for it |
| `--logic L` | logic for the verification condition (default `ALL`) |
| `--timeout SEC` | wall-clock limit per solver call |
| `--no-syntactic`, `--no-semantic` | run only one of the two checks |
| `--print-vc` | print the generated SMT-LIB file and exit |
| `--keep-vc` | leave the verification condition on disk |

## The verification condition

For assumptions `A_i` and constraints `C_j` over the variables `X` introduced by
`declare-var`, a solution is correct iff

```
forall X. (and A_i) => (and C_j)
```

so the checker asserts the negation, `(and A_i) and (or (not C_j))`, over `X`
declared as free constants and expects `unsat`.  Existential quantification
distributes over the disjunction, so a single query is both sound and complete
for the whole constraint set.

`(inv-constraint inv pre trans post)` is expanded first into the three standard
constraints over fresh state variables:

```
pre(x)                => inv(x)
inv(x) and trans(x,x') => inv(x')
inv(x)                => post(x)
```

Use `--print-vc` to inspect exactly what is sent to the solver.

## The grammar check

For a solution body `t` the checker computes, bottom-up, the set of
nonterminals that derive `t`; the check passes iff the grammar's start symbol
(the first declared nonterminal) is in that set for the whole body.  Chain
rules such as `A -> B` keep the term unchanged, so the set for a single term is
closed under a fixed-point iteration; every other rule shape strictly decreases
term size, which makes the recursion well founded.

Details worth knowing:

* Solutions are `let`-expanded first, since solvers routinely print
  `let`-abbreviated terms while grammars (SyGuS `BfTerm`s) are binder free.
* If the solution names its parameters differently from the `synth-fun`, they
  are renamed positionally before matching, so grammar productions that mention
  the formals by name still apply.
* `(Constant S)` matches literals of sort `S`, including the forms solvers
  print for negative and rational constants (`(- 1)`, `(/ 1 2)`) and bit-vector
  constants (`#x0f`, `#b01`, `(_ bv3 32)`).  A numeral matches both `Int` and
  `Real`.
* `(Variable S)` matches a formal parameter of the `synth-fun` whose sort is
  `S`.  Variables introduced by `declare-var` are not in scope inside a
  solution, so they are not accepted.
* Sorts are compared after expanding `define-sort` aliases.
* A `synth-fun` with no grammar imposes no syntactic restriction, and the check
  reports that it is vacuous.

## Limitations

* The semantic check is only as good as the SMT solver: a timeout or `unknown`
  is reported as `unknown`, never as `correct`.
* The SyGuS 2.1 oracle and `chc-constraint` commands are rejected as
  unsupported rather than silently ignored.
* `let` inside a grammar production is not part of SyGuS v2's `BfTerm` syntax;
  if one is found the syntactic check reports `inconclusive` instead of
  guessing.
* Well-sortedness of the solution body is left to the SMT solver in the
  semantic check; the checker does not implement its own type checker.

## Layout

```
sygus-check              command line entry point
sygus_check/sexpr.py     s-expression reader/printer
sygus_check/terms.py     substitution, let-expansion, literal recognition
sygus_check/problem.py   SyGuS v2 parser, inv-constraint expansion
sygus_check/solution.py  solution-file parser
sygus_check/syntactic.py grammar derivability
sygus_check/semantic.py  verification condition generation and solver dispatch
sygus_check/check.py     orchestration and verdict
tests/run_tests.py       unit tests plus end-to-end cases in tests/cases
```

Run the suite with `python3 tests/run_tests.py` (needs `cvc5` on `PATH`, or set
`SYGUS_CHECK_SOLVER`).
